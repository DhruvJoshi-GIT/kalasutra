# Decisions log (append-only)

Format: date · decision · why · what it rules out.

- **2026-09-04 · Reuse `pickindian` as the base, do not restart.** It already has the buyer storefront, Prisma schema, auth, UI kit and warm craft palette. Rules out: a fresh scaffold, a different framework.
- **2026-09-04 · Build order: website → key AI features → Android app.** User's call. The artisan portal is built on the web first so every AI feature is exercised through a browser before the mobile shell exists. Rules out: starting with Expo.
- **2026-09-04 · Sarvam AI is the language provider** (Saarika/Saaras ASR, Bulbul TTS, Mayura translation). 1,000 free credits, Indian model, covers all mainstream Indian languages. Claude (`claude-opus-5`) handles only what Sarvam cannot: schema-constrained listing JSON, photo QC via vision, pricing reasoning. Rules out: Whisper, Google STT, Claude generating Hindi copy directly.
- **2026-09-04 · Sarvam credit discipline is phase-0 work.** One wrapper (`src/lib/ai/sarvam.ts`), `SARVAM_FIXTURES=1` replay mode for dev, content-hash cache so nothing is billed twice. Rules out: iterating UI against the live API.
- **2026-09-04 · Cloud AI APIs are allowed** (user confirmed). The PRD's "all services local" constraint is relaxed for AI only; DB and storage stay local.
- **2026-09-04 · Mobile auth = phone OTP + JWT, separate from NextAuth.** Artisans have phones, not emails; NextAuth v5 fights React Native. Web NextAuth untouched. Rules out: NextAuth on the mobile app.
- **2026-09-04 · No agent memory; `D:\swadesh` is the only knowledge base.** User instruction. `progress.md` is the handoff file, updated after every significant execution.
- **2026-09-04 · Node installed system-wide via winget; PostgreSQL run from portable EDB zip binaries under `D:\swadesh\tools\pgsql` with data in `D:\swadesh\pgdata`.** Docker Desktop on Windows Home needs WSL2 + reboot — not worth the risk mid-hackathon. Portable Postgres needs no admin, no service, and is deleted by removing the folder. Rules out: Docker for the DB (compose file can still be added later for judges / other machines).
- **2026-09-04 · Embeddings stored as `Float[]` on Product; kNN computed in Node, not pgvector.** pgvector has no easy Windows build and the catalogue is ~500 rows × 1024 dims — in-process cosine over that is sub-millisecond. Rules out: pgvector for now (revisit if the catalogue passes ~20k rows).
- **2026-09-04 · Synthetic catalogue rows are flagged `isSynthetic = true` and disclosed.** Undisclosed synthetic data is a judging risk; disclosed + anchored to the 13 real seed SKUs reads as rigour.
- **2026-09-04 · Uploads go to local disk (`<repo>/storage`, gitignored), served by `GET /api/files/<key>`.** No MinIO/S3 for the website phase — one less moving part, and `src/lib/storage/index.ts` is a three-function seam that swaps to S3/R2 without touching callers. Rules out: MinIO in phase 1.
- **2026-09-04 · Artisans sign in on the web with the existing NextAuth credentials flow; the `Role` enum gained `ARTISAN` and `BUYER`, and the JWT now carries `role`.** `/artisan/*` is protected in `src/middleware.ts` (no session → login; wrong role → `/sell`). Phone-OTP + JWT is still the plan for the mobile app only.
- **2026-09-04 · `/sell` is the single onboarding page** — signed-out visitors create account + profile in one form (`POST /api/auth/signup` with `role: 'ARTISAN'`); signed-in buyers upgrade in place (`POST /api/artisan/profile` promotes them, then `useSession().update()` refreshes the JWT). Rules out: a separate artisan signup page.
- **2026-09-04 · Multi-vendor orders keep order-level status (PRD US 1.4) but the artisan API filters line items to their own products and reports their own line total.** Per-item fulfilment status is a post-hackathon refinement.
- **2026-09-04 · Products that were ever ordered are deactivated, never deleted** (`DELETE /api/artisan/products/:id`), so order history stays intact.
- **2026-09-04 · No more Artifacts.** User instruction: do not publish design canvases or pages as Artifacts; show all work as local HTML files or on localhost for review. Rules out: the Artifact tool for this project.
- **2026-09-04 · Interaction language ported from the user's own repo `DhruvJoshi-GIT/PrithviNet`** (behaviour only, not its visuals): hard offset shadow `3px 3px 0` that lifts to `4px` + `translate(-1,-1)` on hover and presses flat (`translate(3,3)`, shadow 0) on click (`.neo`); cards lift to `5px` (`.neo-card`); nav rows nudge `translate(2,2)` on press (`.neo-press`); inputs grow a marigold offset shadow on focus; theme toggle uses `document.startViewTransition` with a circle reveal from the fixed bottom-right toggle (`::view-transition-new(root)` clip-path animation, 0.9s), theme stored in `localStorage['ks-theme']`, `.dark` class on `<html>`, anti-flash inline script in `<head>`. Light (paper) is the default.
